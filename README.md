# EE Downloader — أندرويد

**تطبيق أندرويد مستقل من الصفر** لتنزيل ملفات الفيديو والصوت المباشرة (نسخة MVP 0.1.0). المرجع الوظيفي كان فكرة تطبيقات تنزيل الوسائط، لكن لا يتضمن هذا المشروع كودًا أو شعارات أو موارد مأخوذة من تطبيق Snaptube.

## الوظائف المتاحة الآن

- متصفح WebView داخلي مع شريط عنوان وأزرار الرجوع والتقدم والتحديث.
- اكتشاف عناوين الوسائط المباشرة `MP4`, `WebM`, `M4A`, `MP3` وغيرها من حركة الشبكة وعناصر HTML5 `video` / `audio`.
- عرض قائمة الروابط المكتشفة ووسوم الجودة **فقط إذا كانت ظاهرة في الرابط** (مثل `720p`, `1080p`).
- تنزيلات في الخلفية باستخدام **Android DownloadManager** مع إظهار التقدم، حفظ الملفات في مجلد Downloads، فتح الملفات المكتملة وإلغاء التنزيلات.
- استقبال رابط من زر «مشاركة» في تطبيقات أخرى، أو لصقه يدويًا.
- واجهة عربية داكنة. التطبيق مبني باستخدام Java وAndroid SDK دون مكتبات UI خارجية.
- يدعم أجهزة Android 10 فما فوق، ومنها أجهزة Samsung ARM64؛ ملف APK الناتج **Universal** لأن المشروع لا يستخدم مكتبات Native.

## قيود النسخة الأولى — مهمة

- ليست نسخة مطابقة لكل وظائف Snaptube.
- لا يمكن تنزيل فيديو محمي بـ DRM، ولا تجاوز CAPTCHA أو منع الموقع أو تسجيل الدخول.
- لا يدعم تحويل فيديو إلى MP3؛ يدعم تنزيل روابط MP3 الأصلية الموجودة.
- لا يدعم تنزيل HLS (`m3u8`) أو DASH (`mpd`) وتجميع المقاطع حتى الآن، لكنه يتعرف على هذه القوائم ويعرض رسالة توضيحية.
- لا يجلب جودة جديدة من خادم الموقع؛ يعرض فقط الوسائط والجودات التي يكشفها المتصفح.
- روابط `blob:` ومواقع الفيديو التي تستخدم مشغلات محمية أو توقيعات خاصة قد لا تظهر أو لا تعمل. إن كان الموقع يقدم ملفًا مباشرًا يمكن تنزيله.
- التطبيق لا يزيل العلامات المائية ولا يجتاز القيود التقنية. حمّل فقط الوسائط التي تملك حق تنزيلها.

## البناء عبر GitHub Actions

1. ارفع **كامل الملفات الموجودة داخل هذا المشروع** إلى الفرع `main` من المستودع `ee`.
2. افتح GitHub → `ee` → **Actions** → workflow: **Build EE Downloader APK**.
3. عند نجاح التنفيذ افتح التشغيل → **Artifacts** → **EE-Downloader-debug-APK**.
4. داخل ZIP الناتج ستجد `ee-downloader-debug.apk` و`SHA256SUMS.txt`.

كل دفعة إلى `main` تشغّل اختبارات Java وبناء APK. يمكن كذلك تشغيل البناء يدويًا عبر `workflow_dispatch`.

## البناء محليًا (Windows / Android SDK)

- Java 17، Android SDK Platform 35 وBuild Tools 35.0.0، Gradle 8.9.
- نفّذ `gradle :app:testDebugUnitTest :app:assembleDebug` من جذر المشروع.
- الملف الناتج `app/build/outputs/apk/debug/app-debug.apk`.

> ليس في هذا المشروع Gradle Wrapper JAR: إعداد GitHub Actions يثبّت Gradle 8.9 مباشرة لتجنب إضافة ملف ثنائي غير موثّق.

## اقتراحات التطوير التالي

1. محرك HLS غير المشفّر مع استئناف تحميل المقاطع ودمجها في ملف قابل للتشغيل.
2. استخراج بيانات الجودة من `master.m3u8` حيث يُسمح بذلك.
3. محرك تحويل صيغة الصوت محليًا بإذن المستخدم.
4. تحسينات الواجهة على الأجهزة القابلة للطي، والبحث عن التنزيلات وإدارة التخزين.
5. اختبارات instrumented على أجهزة فعلية ومراجعة استقرار WebView.

## الخصوصية

تتم المعالجة محليًا في الجهاز. لا يتضمن المشروع تحليلات، ولا يرسل سجل التصفح إلى خادم خاص بالتطبيق. المواقع المفتوحة داخل WebView لها سياسات الخصوصية الخاصة بها.

## رفع المشروع من Termux إلى المستودع ee

إذا كان مستودعك فارغًا ولم تسمح صلاحيات التطبيق بالرفع عبر الاتصال المباشر:

1. نزّل ملف `ee-downloader-source.zip` من المحادثة، ثم ثبّت `git` و`gh` و`unzip` عبر Termux.
2. نفّذ `termux-setup-storage` مرة واحدة لمنح Termux الوصول إلى مجلد Downloads.
3. فك الضغط: `cd ~/storage/downloads && unzip ee-downloader-source.zip`.
4. اذهب للمجلد: `cd ee-downloader`.
5. تأكد من تسجيل الدخول لحساب GitHub المناسب عبر `gh auth status`، ثم نفّذ `bash UPLOAD_TERMUX.sh`.

**تنبيه:** يرفع السكربت الملفات إلى المستودع المحدد `hald2020aa-hue/ee` فقط، ولا يحذف مستودعات أخرى. إذا كانت بيانات Git أو صلاحية الرفع ناقصة، يخرج برسالة واضحة دون الادعاء أن الرفع نجح.
